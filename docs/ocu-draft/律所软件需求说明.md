## 1. 一句话定位

**面向企业老板的法律智能助手。** 老板有任何法律问题、任何需求、任何困惑，都可以直接问——不限于案件管理、合同审查、法规检索，而是"老板脑子里冒出来的任何法律相关的问题"都能得到大模型解答。

核心交互形态：**老板把问题拍下来（或发来微信收到的图/文件），大模型看懂后解答。**

---

## 2. 为什么是"任何问题都需要解答"

企业老板不是法律专业人士，他的真实使用场景是：

- 收到一份合同照片 → "这合同有没有坑？"
- 微信里合作方发来一段语音/文件 → "这算不算违约？"
- 遇到劳动纠纷截图 → "我作为老板该怎么应对？"
- 想看看某条法规 → "新公司法对注册资本有什么要求？"
- 案件进度疑问 → "我的案子到哪一步了？"

所以系统**不预设问题类型**，对所有输入（文字/图片/文件）统一走"识别 → 推理 → 解答"管线。范围可逐步扩展到案件管理、合同审查、法规检索等模块，但 V0.01 先打通"老板提问 → 得到解答"这条主干。

---

## 3. 三套 API Key 架构（全系统统一规范）

所有系统（评估报告审查系统、海关系统、本律所软件）共用同一套 3-key 策略：

| 角色 | 模型 | 用途 | 启用时机 |
|------|------|------|----------|
| **主力 LLM** | **hy3（混元文字推理）** | 所有文字推理、法律解答、对话 | 默认首选 |
| **视觉模型** | **混元视觉（hunyuan-vision）** | 图片/文件中的图表、文字、场景识别 | 输入含图片/文件时调用 |
| **备用 LLM** | **deepseek** | 当 hy3 的 token 额度耗尽时临时顶上 | hy3 返回限额/失败时自动切换 |

**降级逻辑（代码里实现）：**
```
收到问题
  ├─ 有图片/文件？ → 先调 混元视觉 提取内容 → 得到文字描述
  └─ 纯文字？ → 跳过视觉
        ↓
  调 hy3 生成解答
        ↓
  hy3 失败/限额？ → 自动切 deepseek 生成解答（标注"由备用模型生成"）
```

> 注意：三套 key 的管理方式沿用既有系统——key 放服务端 `.env`，**不进仓库**。部署文档见 `DEPLOY-V0.01-OCX.md`。

## 6. V0.01 交付范围（本次先做）

**H5 客户端（企业老板看的界面）：**
1. 移动端优先的 H5 页面，老板手机浏览器打开即用。
2. **输入方式**：
   - 拍照上传（手机摄像头）
   - 相册/文件选择（含微信收到的图、文件）
   - 文字输入框（直接打字问）
3. **处理管线**：图片/文件 → 混元视觉识别 → hy3 解答（失败切 deepseek）。
4. **结果展示**：解答以清晰排版呈现，可显示"由哪个模型生成"。
5. （可选）本地历史记录。

**不做（留待后续版本）：** 案件管理后台、合同审查专项、法规库检索、多用户/登录体系、付费等。
